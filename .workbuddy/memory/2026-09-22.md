## 转向：丰富元件兼容性（C/L、受控源）—— 立项前的现状勘查

苏霖韵指示下一步做「丰富元件兼容性，如电容电感、受控源」。开工前先勘查，**查出一个严重缺陷**。

### ★★ 严重缺陷：电感把理想电压源短路时，给出报「通过」的错答案

电路：`V1 1-0 = 10V`、`L1 1-0`、`R1 1-2 = 5Ω`、`R2 2-0 = 5Ω`。
直流下 L 是短路 → V1 被短路 → 约束集 `V1 − V0 = 10V` 与 `1 ≡ 0` **矛盾**，无解。

**ngspice 独立复核（第三方）**：
```
Warning: singular matrix:  check node l1#branch
Note: Dynamic gmin stepping failed
Note: True gmin stepping failed
Note: source stepping failed
→ NgSpiceCommandError: Command 'run' failed
```
三种收敛策略全失败 → **该电路确实无解**。

**circuit_agent 的表现**：
```
化简报告：电容视为开路，移除 2 条支路（V1, L1）；电感视为短路，合并节点组：0≡1
剩余元件：R1, R2
run_all 总判定 = True            ← 报"通过"
节点电压 = {'1': '0', '2': '0'}   ← 节点 1 变 0V：10V 约束凭空消失
支路电流 = {'R1': '0', 'R2': '0'}
```

**根因**：`dc_reduce.py:128-134` 对"两端被合并到同一节点"的元件一律当"被短接、等价于消失"而移除。
这对**电阻**是对的（0Ω），对**电压源**是错的 —— 电压源被短接意味着约束矛盾，必须报错。

**为什么三法互校拦不住**：化简发生在**三条路径之前**，三方一致地解的是"被化简歪了"的电路。
这正是"跨实现对账/换路径"要补的那类盲区，但这次连跨工具对账也在化简之后跑，同样拦不住。
**功率守恒也拦不住** —— 全零解的 ΣP = 0 平凡成立。

**违反本项目最硬的约束**：「不静默降级」。删掉一个电压源让电路"变得可解"，属于最典型的静默降级。

### 次要缺陷：化简摘要文本张冠李戴

电路：`V1 1-0=10V`、`L1 1-2`、`R1 1-2=5Ω`、`R2 2-0=5Ω`（**没有电容**）。
摘要输出："**电容视为开路，移除 2 条支路（L1, R1）**"。
根因：`ReductionReport.removed` 把「C 开路移除」与「被电感短接而移除」混在同一个 list，
而 `summary()`（`dc_reduce.py:65-67`）把整个 list 一律冠以"电容视为开路"。
→ 需要按原因分组，各自陈述。

同类问题：`summary()` 里孤立节点的解释硬编码"这些点只能经**电容**供电"，
但孤立也可能是**电感合并**造成的（实测就是这个情形）。

### ★ 第三条缺陷（本次新查出）：被合并掉的节点被误报为"孤立节点"

复现 B（`V1 1-0=10V`、`L1 1-2`、`R1 1-2=5Ω`、`R2 2-0=5Ω`，**无电容**）摘要：

```
直流稳态化简：电容视为开路，移除 2 条支路（L1, R1）；电感视为短路，合并节点组：1≡2；
化简后孤立节点：['2']（这些点只能经电容供电，直流稳态下悬浮 —— 这是正确结论，不是错误）。
```

三处都错：
1. 无电容却说"电容视为开路，移除 L1, R1"（`removed` 混装两因，见上）；
2. 节点 `2` **不是孤立**，它是被 `L1` 合并进节点 `1` 了，节点名仍存在于 IR；
3. "只能经电容供电"的解释方向完全反了。

根因：`dc_reduce.py:146-147`
```python
used = {n for c in rewritten for n in c.nodes}
report.isolated_nodes = sorted(set(circuit.nodes) - used - {circuit.ref_node})
```
`rewritten` 里的节点名已被 `rep()` 换成**代表元**，所以「被合并掉的原节点名」必然
落在 `set(circuit.nodes) - used` 里 → 被当成孤立节点。
修法：孤立节点应基于**合并后仍存在的代表元**计算，并把"被合并掉的节点"单列一组
（如 `merged_away`），两者语义不同，不可混。

### 附：化简后"两端合一"的五类元件，正确处理各不相同（修复规格草案）

| 元件 | 两端被合并时 | 正确处理 |
|---|---|---|
| **V** | 被短路 | `value != 0` → **无解，必须报错**；`value == 0` → 视为导线，可删 |
| **R** | 被短路 | 可删，但应显式给出 `i = 0`（不是从报告里消失） |
| **I** | 被短路 | 可删，但应显式给出 `i = 源值`（该支路电流由定义确定） |
| **L** | 被短路（自身参与合并） | 与并联 L 分流不定，需留痕"电流不定" |
| **C** | 已在第 2 步作为开路移除 | 不涉及 |
