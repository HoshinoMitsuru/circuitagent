### 2. ★ 测试当场揪出的三处真实缺陷

| # | 缺陷 | 证据 | 根因 | 修法 |
|---|---|---|---|---|
| 1 | **网表往返丢"被采样支路"** | `H1: 被采样支路 R1 → Vsense_R1` | `H`/`F` 卡引用的是系统插的 0V 探针；光看卡片分不开 R1 与 Vsense_R1 | 写机器可读语义标记 `* ca-ctrl H1 mode=I ref=R1 sense=Vsense_R1`，`from_spice` 读它还原 |
| 2 | **界面"被采样支路"永远显示（未定）** | `controlled[].ref` 是**受控源自己**的位号，而选项里刻意排除了自己 → 永远选不上 | 三个支路身份挤在一个 `sampling` 字段里 | 拆成 `sampled_ref` / `probe_ref` / `sampling_ref` / `sampling_is_probe` |
| 3 | **改名把用户手写的空格抹掉** | `3*u_2 + 5` → `3*uA+5` | `rewrite_symbol` 把表达式拆成记号再拼回去 | 改成**带记号边界**的正则，只替换命中的字面量 |

三处都属于同一类：**不会算错，只会指错**。第 1、2 条正是用户点名的"避免参数指向错误"。

### 3. 顺带修的一处（属第 3 条的延伸）

`Control.describe()` / `controlled_note()` 原本显示 `2000·i(Vsense_R1)` ——
用户翻遍题目也没有 `Vsense_R1` 这个元件。改成
`2000·i(R1)（经 0V 探针 Vsense_R1 取出，不是题目元件）`：**名字指向用户认得的东西，机制另说**。

### 4. 语义标记的设计纪律（照抄回绘 SVG 的 `data-ca-*`）

* 卡片/几何仍是**权威**（谁接谁、增益多少只认卡片）；标记只补"身份"这一类卡片表达不了的信息。
* 标记与卡片不符 → **以卡片为准** + 原因写进 diagnostics，绝不按标记改连接。
* 外来网表无此标记 → **原样不动**（命名空间 `ca-ctrl` 保证不误吃别人的注释）。
* ★ **顺序**：先按卡片查合法性（H/F 控制端必须是电压输出元件），**再**用标记还原 ref。
  反过来标记会把一张本来跑不起来的网表"修好"，用户以为读进来了、其实读的是另一张电路。

## 四、★ 已确认但本轮**不修**的缺陷（用户已拍板：先记录）

**自动版式对并联支路会把两条排在同一轴线上。**

* 版式自检报 `E1 与 R3 的轴线几乎重合（并联支路被排在同一位置）`、`roundtrip_safe=False`；
* 回导时两个符号叠在一起、两端被判成同一个结点 → 被记为 `short_circuit` 一起消失；
* 实测：5 元件电路（V1/R1/R2/E1/R3）回导只剩 3 个（V1/R1/R2）；
* `mode` 取 `auto` / `radial` / `grid` **三种都复现**（`geom` 因为测试电路没有视觉坐标而无法渲染）。

★★ **关键**：三法互校、跨实现对账、功率守恒**全都拦不住** ——
大家解的都是那张少了两条支路的电路，而它自己完全自洽、ΣP 也等于 0。
唯一能抓住它的是**版式自检 + `skipped_components` 结构化报出**这两步（都已接上），
外加一条纪律：**`roundtrip_safe=False` 的插图不许拿去几何回导**。

修的时候要动 `app/ir/render.py` 的布局算法（并联支路按分支簇分组、分到不同轴线），
影响面涉及全部版式相关自检与回绘验收，单独开一轮做。
